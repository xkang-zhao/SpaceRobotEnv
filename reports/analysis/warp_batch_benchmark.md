# Cube 多 world 物理回放基准

2026-09-08，NVIDIA A800 80GB PCIe。MuJoCo / MuJoCo Warp 3.12.0、Warp 1.17.0、NumPy 2.4.6；生成控制序列使用 Pinocchio 4.1.0。

**512 个 world 的纯物理吞吐为单核 CPU 基线的 27.1 倍。** 单 world Warp 仍慢于 CPU。本结果支持继续实现 GPU 批量 state 环境，但不代表完整抓取、视觉或数据采集吞吐。

原始数据：[warp_batch_benchmark.json](warp_batch_benchmark.json)。

| 后端 | world 数 | 纯物理子步/秒 | 含传输子步/秒 | 相对单核 CPU | 每批控制周期 ms（含传输） | 进程 GPU 占用 MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| CPU | 1 | 20,109 | — | 1.00× | 4.97（仅物理） | — |
| Warp | 1 | 1,678 | 1,671 | 0.083× | 59.86 | 658 |
| Warp | 32 | 46,244 | 46,046 | 2.30× | 69.50 | 726 |
| Warp | 128 | 157,758 | 157,170 | 7.85× | 81.44 | 986 |

各行是单次完整回放的平均值，没有重复测量的置信区间。CPU 基线使用单核 `mj_step(..., nstep=100)`，不是多核采集器；吞吐倍率分母为本次测得的单核物理吞吐。

## 工作负载与计时

- 在 CPU 上以 seed=7 生成一条已确认成功的 Cube 抓取控制序列，共 96 个控制周期，每周期 100 个物理子步，timestep 为 0.0005 秒。
- 各 world 复制相同初始状态、回放相同关节/夹爪控制；不包含不同 seed 或不同任务的混合负载。
- 编译、预热、Graph 捕获和初始状态恢复在计时外进行。状态恢复原地复制 GPU 缓冲区，避免 Graph 引用已替换的内存。
- GPU 的控制上传、Graph 执行、qpos/qvel 与溢出标记回读分别同步计时。CPU 状态参考和所有 GPU world 在每个控制周期进行比较，校验耗时不计入吞吐。
- “含传输”是上述三个阶段耗时之和，不包含 IK、planner、Python 观测组装、接触成功判定、相机、编码或写盘。
- 512 world 每周期平均控制上传 0.074 ms、物理步进 93.843 ms、状态回读 0.238 ms。这里仅回读必要状态，不是单环境后端的完整 `MjData` 回读，因此不能直接与单环境端到端 benchmark 比较。

## 状态一致性与显存

四个规模的整个轨迹均为有限状态，没有检测到容量溢出。各规模与 CPU 的最大 qpos 分量误差不超过 `0.000912`，最大 qvel 分量误差不超过 `0.03578`，均小于预先设置的 `0.005` / `0.1` 容差。

qpos 混合位置、关节角和四元数，qvel 混合线速度与角速度；上述数值是分量绝对误差，不应统称为米或速度误差。原始数据的 `max_world_*_spread` 表示相对于 world 0 的最大分量偏差；多 world 之间不是逐位一致。这些数值检查不等同于不同 seed 的成功率验证。

显存是回放结束、释放资源前的当前进程 GPU 占用，包含上下文与缓存，不是峰值。四个规模依次执行，保留的驱动缓存也可能影响后续行。原始数据另记录 Warp 内存池在用量，512 world 为 85.2 MiB；该值不包含全部 CUDA 进程开销。

Warp 对部分几何组合发出了 MultiCCD 支持差异提示。本次仍保持原始场景、求解器设置及抓取标定，未调整碰撞几何或成功阈值。

## 复现与验证

从仓库根目录执行，需先安装项目、Pinocchio 和 `.[warp]` 可选依赖：

```bash
python scripts/benchmark_batch_physics.py --worlds 1 32 128 512 --seed 7 \
  --output /tmp/warp_batch_results.json
RUN_WARP_TESTS=1 python -m unittest discover -s test -p 'test_batch_physics_benchmark.py'
```

本次上述四个规模完整回放退出码为 0；4 项测试通过，包括真实 CUDA 四 world 回放、预热恢复、非法控制序列以及非零 world 异常检测。输出文件拒绝覆盖，重复运行需选用新路径。

下一阶段应加入逐 world 控制、独立 seed/reset、批量状态观测和接触成功计数，再比较实际抓取成功率。随后再处理批量 IK；本基准尚未验证这些能力。
